# Лабораторная работа №11 — React: компоненты, props и state

Учебное одностраничное приложение на React + JavaScript. В одном интерфейсе реализованы задания трех уровней сложности из вариантов лабораторной: базовый счетчик лайков, средний список задач и повышенный планировщик расходов. Переключайте задания карточками в разделе «Выберите задание».

## Запуск

Требуется Node.js 18 или новее.

```bash
cd LAB11
npm install
npm run dev
```

Откройте адрес, который Vite покажет в терминале (обычно `http://localhost:5173`). Для проверки production-сборки выполните `npm run build`.

## Реализованные задания

| Сложность | Вариант | Реализация |
|---|---:|---|
| Базовый | №1 — счетчик лайков | `LikeButton` получает подпись и начальное значение через props; лайки и состояние нажатия хранятся в `useState`. Кнопка добавляет/убирает лайк. |
| Средний | №8 — список задач | `TodoList` хранит задачи, фильтр и поле ввода; `TodoItem` получает задачу и обработчики через props. Можно добавлять, отмечать выполненные, удалять и фильтровать задачи. |
| Повышенный | №16 — планировщик расходов | `ExpensePlanner` хранит список расходов и фильтр категорий; `ExpenseForm` сообщает о добавлении через callback prop, `ExpenseList` получает записи и обработчик удаления через props. Отображаются сумма, количество и средний расход; записи сохраняются в `localStorage`. |

## Структура компонентов и поток данных

- `App` выбирает демонстрацию и передает `label` / `initialLikes` компоненту `LikeButton`.
- `TodoList` → `TodoItem`: задача и callbacks передаются вниз через props; события возвращаются родителю вызовом callbacks.
- `ExpensePlanner` → `ExpenseForm` / `ExpenseList`: родитель управляет данными, дочерняя форма передает новую запись через `onAdd`, список сообщает об удалении через `onDelete`.
- Props являются входными данными и напрямую не изменяются. Изменения состояния выполняются через setter-функции `useState`.

## Проверка сценариев

| № | Сценарий | Ожидаемый результат |
|---:|---|---|
| 1 | Открыть базовое задание | Видно 128 лайков; подпись пришла компоненту через props. |
| 2 | Нажать «Мне нравится» дважды | Счетчик сначала увеличивается на 1, затем возвращается к исходному значению; состояние кнопки переключается. |
| 3 | Добавить пустую задачу | Пустое значение не добавляется; приложение остается работоспособным. |
| 4 | Добавить задачу, отметить, включить фильтр «Выполнено» | Новая задача отображается, чекбокс меняет состояние, фильтр показывает только выполненные. |
| 5 | Добавить расход с пустым названием или суммой 0 | Показано понятное сообщение валидации, запись не создается. |
| 6 | Добавить корректный расход, затем обновить страницу | Итоговая сумма и количество обновлены; новая запись сохраняется в `localStorage`. |
| 7 | Отфильтровать расходы по категории и удалить одну запись | В списке остаются записи выбранной категории; после удаления пересчитываются показатели. |

## Дополнительное задание

Планировщик использует `localStorage` для сохранения списка расходов между перезагрузками. Состояние фильтра, полей формы, задач и счетчика локально для соответствующих компонентов.
